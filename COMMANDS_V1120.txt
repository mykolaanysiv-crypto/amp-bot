АМПасадори v1.12.0 — ПОЧЕРГОВІ КОМАНДИ HEROKU UPDATE
======================================================

Сценарій: оновлення поверх поточного production Git repo без локального запуску.
Heroku app: amp-bot-ver-1-5-0

1) ПЕРЕЙТИ В ПОТОЧНУ РОБОЧУ GIT-ПАПКУ
-------------------------------------
cd ~/Downloads/amp_bot_v1103

git status
git remote -v

Якщо heroku remote відсутній:
heroku git:remote -a amp-bot-ver-1-5-0

2) LOGIN + BACKUP З ВЕРИФІКАЦІЄЮ
--------------------------------
heroku login

Після того як v1.12.0 уже скопійовано у repo, доступний helper:
./scripts/heroku_capture_verified_backup.sh amp-bot-ver-1-5-0

До накладання v1.12 можна використати стандартно:
heroku pg:backups:capture -a amp-bot-ver-1-5-0
heroku pg:backups -a amp-bot-ver-1-5-0

3) ВЗЯТИ ПОТОЧНИЙ HEROKU COMMIT ЗА ОСНОВУ
----------------------------------------
git fetch heroku main
git reset --hard heroku/main

4) РОЗПАКУВАТИ v1.12.0
----------------------
rm -rf /tmp/amp_bot_v1120_release
mkdir -p /tmp/amp_bot_v1120_release
unzip -q ~/Downloads/amp_bot_v1120.zip -d /tmp/amp_bot_v1120_release

5) НАКЛАСТИ РЕЛІЗ ПОВЕРХ ПОТОЧНОГО REPO
--------------------------------------
rsync -av --delete \
  --exclude='.git' \
  --exclude='.env' \
  --exclude='.venv' \
  --exclude='__pycache__' \
  --exclude='.pytest_cache' \
  /tmp/amp_bot_v1120_release/amp_bot_v1120/ \
  ./

6) ПЕРЕВІРКА ПЕРЕД COMMIT
-------------------------
cat VERSION.txt
# очікується: 1.12.0

git check-ignore .env
git status --short
git diff --stat

Перевірити секрети Heroku без показу значень:
for VAR in BOT_TOKEN WEB_SESSION_SECRET MONOBANK_TOKEN DATABASE_URL; do
  if [ -n "$(heroku config:get "$VAR" -a amp-bot-ver-1-5-0)" ]; then echo "✅ $VAR"; else echo "❌ $VAR"; fi
done

7) COMMIT
---------
git add -A
git status
git commit -m "Upgrade AMP to v1.12.0 production engineering"

8) DEPLOY
---------
git fetch heroku main
git push heroku HEAD:main

Release phase автоматично:
- виконує legacy compatibility bootstrap;
- виконує Alembic upgrade head;
- запускає production preflight.

9) УВІМКНУТИ ОКРЕМИЙ WORKER
----------------------------
heroku ps:scale web=1 worker=1 -a amp-bot-ver-1-5-0

ВАЖЛИВО: worker є окремим process type. Переконайтеся, що ваш Heroku plan дозволяє потрібну кількість dyno/process resources.

10) ПЕРЕВІРКА ПРОЦЕСІВ
----------------------
heroku ps -a amp-bot-ver-1-5-0

Очікується щонайменше:
web.1    up
worker.1 up

11) LOGS
--------
heroku logs --tail -a amp-bot-ver-1-5-0

У JSON logs поле service має бути web або worker.

12) BACKUP VERIFICATION MARKER
------------------------------
Після першого deploy v1.12 рекомендується виконати helper ще раз:
./scripts/heroku_capture_verified_backup.sh amp-bot-ver-1-5-0

Або вручну:
heroku pg:backups:capture -a amp-bot-ver-1-5-0
heroku run -a amp-bot-ver-1-5-0 -- python -m scripts.mark_backup_verified "Heroku PGBackup verified"

Перевірити marker:
heroku run -a amp-bot-ver-1-5-0 -- python -m scripts.verify_backup_marker

14) OPTIONAL SENTRY
-------------------
Якщо використовуєте Sentry:
heroku config:set SENTRY_DSN="..." APP_ENV=production LOG_LEVEL=INFO -a amp-bot-ver-1-5-0

Не додавайте SENTRY_DSN, BOT_TOKEN, MONOBANK_TOKEN, WEB_SESSION_SECRET або DATABASE_URL у Git.
