# AMP XP v1.22.0-rc1 — фінальна передрелізна збірка

## Статус
**Release candidate для приймального тестування, НЕ production-ready**. База — v1.21.0 із послідовними UX-змінами Iterations 1–4. Це повний вихідний код для розпакування. Існуючу production-базу, Heroku та дані користувачів не змінено.

## Реалізовано
- Єдиний JavaScript/dialog механізм модальних форм для підключених модулів: квести, задачі, можливості, опитування, швидкі XP, винагороди, бейджі, активності, завдання команди, цілі, розіграші, сезони, шаблони розсилок, звіти щодо донатів та форми запитань опитування.
- Повернення перенесених DOM-форм після закриття, попередження про незбережені зміни, обробка помилки відкриття діалогу, захист від повторного submit, мобільні стилі та reduced motion.
- Технічні повідомлення про нову версію адресовані тільки активним Telegram-користувачам з роллю superadmin із ключами дедуплікації та distributed job lock.
- VERSION.txt змінено на 1.22.0-rc1, щоб не плутати збірку з v1.21.0. Це **нова версія для тестування**; при запуску на ізольованому середовищі механізм сповіщення може створити повідомлення для тестових суперадміністраторів.

## Що НЕ підтверджено
- Повний редизайн усіх сторінок до піксельної відповідності макетам не завершено.
- Наскрізне браузерне тестування створення/редагування кожної форми не завершено.
- PostgreSQL 18, Heroku, Telegram delivery, QR/XP, restore backup та всі старі бізнес-тести не пройдено як повний release gate.
- Динамічні форми різних форматів не слід вважати повністю реалізованими в усіх модулях без end-to-end тестів.

## Обов'язкові release gates перед production
1. Окрема PostgreSQL 18 тестова БД та перевірка Alembic поточного head; порівняння зі станом production.
2. Інтеграційні тести: auth/permissions, event create/edit, реєстрації, QR, XP, квести, опитування, швидкі XP, подарунки/донати, Telegram.
3. Браузерний visual QA на 1920, 1440, 1024, 768, 390 і 320px, keyboard/focus/validation.
4. Перевірений backup+restore, CI зелений, smoke/health checks на staging.
5. Окремий дозвіл на deployment/merge після приймання.
