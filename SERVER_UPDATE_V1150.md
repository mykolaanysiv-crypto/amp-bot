# AMP XP / «АМПасадори» v1.15.0 — Targeting, Event Analytics & Opportunity UX

## Що змінено

### 1. Адресні опитування
- Додано три режими доступу: усі активні учасники, обрані зі списку, учасники конкретної події.
- Для подій до аудиторії входять `registered`, `reserved`, `checked_in`, `attended`; waitlist/no-show/cancelled не отримують доступ автоматично.
- Telegram перевіряє право доступу при показі списку, відкритті та старті опитування.
- Публікаційна розсилка надсилається тільки визначеній аудиторії.

### 2. Зрозумілий тижневий звіт
- Термін «ISO-тиждень» прибрано з UI.
- У формі: «Номер тижня (понеділок–неділя)».
- Підпис періоду: наприклад `38-й тиждень 2026 (14.09–20.09)`.

### 3. Аналітика події
У detail-картці події додано: реєстрації, заповнення місткості, частку підтвердженої участі, check-in, no-show, response rate відгуків, середню оцінку, нарахований XP, загальні/унікальні/повторні Telegram-перегляди.

### 4. Можливості
- Default sort = автоматичний: активні з найближчим дедлайном → активні без дедлайну за датою надходження → неактивні/прострочені внизу.
- За ≤3 дні до дедлайну картка у Web підсвічується та показує 🔥.
- У Telegram обидва шляхи відкриття каталогу використовують той самий порядок і текст «У вас є остання можливість долучитись до …».

### 5. Кейси
- Відповідальним можна призначити тільки активного `superadmin`, `admin`, `coordinator` або `ambassador`.
- Обмеження реалізовано не лише у select, а й server-side.

### 6. Бейджі
- Системні та АМПасадорські бейджі можна редагувати: назва, іконка, опис, активність, PNG для АМПасадорських.
- Для built-in автоматичних і donation-бейджів системний критерій/поріг захищені від випадкової зміни.
- Startup seed більше не перезаписує адміністраторське оформлення системних бейджів.
