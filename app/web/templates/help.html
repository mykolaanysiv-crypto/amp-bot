Як можемо допомогти?

Знайдіть коротку інструкцію для подій, учасників, квестів, профілю, безпеки, медіа або звітності. Пошук працює одразу на цій сторінці.

ШВИДКИЙ СТАРТ

Почніть з потрібної задачі

{{ icon('home') }}Початок роботи

Після входу починайте з «Огляду»: він показує операційні сигнали, найближчі події та задачі, які потребують дії.

  1. Використовуйте бокове меню для основних модулів.
  2. Глобальний пошук у верхній панелі знаходить учасників, події та кейси.
  3. «Мій кабінет» містить ваш профіль, досягнення, пароль, 2FA, passkeys і сесії.
  4. На мобільному відкривайте меню через hamburger; клавіша Esc закриває drawer і діалоги.

{{ icon('calendar') }}Події та QR-відмітка

  1. Створіть подію у «Події» та заповніть дату, час, локацію, XP і параметри реєстрації.
  2. QR події використовується для фактичної відмітки присутності. Персональний QR учасника лише ідентифікує людину.
  3. Після сканування присутність ще не є фінальним нарахуванням XP — координатор підтверджує участь.
  4. Після завершення події перевірте no-show, підтвердження та відгуки.
  5. Якщо подію переносите або скасовуєте, система використовує відповідні workflow і сповіщення.

{{ icon('users') }}Учасники та профіль 360°

Картка учасника об’єднує XP, події, квести, волонтерство, ідеї, опитування, бейджі та документи.

  • Базові операційні дані редагуйте лише з permission participants.edit.
  • Чутливі поля та документи доступні лише відповідно до ролей і privacy rules.
  • Не копіюйте персональні дані у сторонні таблиці без робочої потреби.
  • Зміни згод і доступу журналюються.

{{ icon('user') }}Мій кабінет

Це профіль саме користувача вебплатформи, а не окрема форма Telegram-бота.

  • Додайте аватар, роль/підпис, контакти та короткий блок «Про себе».
  • Фото профілю зберігається як приватне staff-медіа.
  • Якщо суперадміністратор пов’яже вебакаунт із participant-профілем, у кабінеті з’являться власні бейджі та показники участі.
  • Світла/темна тема зберігається локально у вашому браузері.

{{ icon('target') }}Квести, XP і цілі

  • Не нараховуйте XP вручну, якщо для активності вже існує автоматичний workflow.
  • Квест має чітко пояснювати умову виконання, доказ і винагороду.
  • Автоматичні QR-квести та інші нарахування захищені від повторного дублювання.
  • Для зміни правил гейміфікації використовуйте відповідні адміністративні модулі — не редагуйте історичні XP-транзакції напряму.

{{ icon('badge') }}Бейджі, серії та винагороди

  • Бейджі можуть бути автоматичними або адміністративними залежно від правила.
  • Серії та ліги формуються з історичних даних і не повинні коригуватися шляхом стирання XP.
  • Винагороди мають вартість у XP та можуть мати обмежений залишок.
  • Профіль користувача показує отримані бейджі як окрему галерею.

{{ icon('survey') }}Опитування та відгуки

  • Створіть опитування, налаштуйте аудиторію і питання.
  • Для подій використовуйте мікровідгуки та стежте за конверсією завершення.
  • Не включайте чутливі поля у звичайні експорти без відповідного permission.

{{ icon('report') }}Аналітика, звіти та експорт

  • «Аналітика» рахується з актуальної бази та показує агреговані показники.
  • «Звіти» формують Excel/PDF за вибраний період.
  • Базовий експорт мінімізує персональні дані; sensitive export доступний лише з окремим permission.
  • Великі вибірки перевіряйте на дату/період перед передаванням донору або партнеру.

{{ icon('media') }}Медіа та файли

  • Media Integrity Center показує missing, orphan, duplicate, MIME, checksum та quarantine-кандидатів.
  • Невідома категорія медіа за замовчуванням приватна.
  • Quarantine — це не hard-delete. Підозрілий файл спочатку проходить review.
  • Міграція database → S3 виконується окремо через dry-run → copy → verify → switch. Deploy самостійно файли не переносить.

{{ icon('shield') }}Безпека акаунта

  • Використовуйте унікальний пароль і не передавайте його в чатах.
  • Telegram 2FA залишається резервним фактором; passkey може використовувати Touch ID, Face ID, Windows Hello або security key.
  • У «Моєму кабінеті» переглядайте активні сесії та завершуйте невідомі.
  • Security Center показує невдалі входи, сесії, 2FA, passkeys, sensitive operations та audit events.

{{ icon('key') }}Права доступу

Прихований пункт меню не є механізмом безпеки — backend permission checks залишаються обов’язковими.

  • Суперадміністратор має повний доступ.
  • Для інших вебакаунтів можна використовувати права за роллю або індивідуальний набір.
  • Зміни permissions і reset пароля фіксуються в аудиті.

  • «Стан системи» показує health, scheduler, worker, backup та інші технічні сигнали.

{{ icon('help') }}Якщо щось не працює

  1. Оновіть сторінку та перевірте, чи проблема повторюється.
  2. Якщо не бачите кнопку або розділ — перевірте роль/permissions.
  3. Не повторюйте destructive дію кілька разів, якщо сервер відповідає повільно.
  4. Зафіксуйте сторінку, час і дію, після якої виникла помилка; не надсилайте паролі, OTP або encryption keys.

FAQ

Часті питання

Чим персональний QR відрізняється від QR події?
Персональний QR ідентифікує учасника. QR конкретної події використовується для check-in саме на цій події.
Чи нараховується XP одразу після QR?
Не завжди. Для подій фактичну участь підтверджує відповідальний workflow; це захищає систему від помилкових нарахувань.
Чи можна видалити медіа одразу?
Проблемні або непотрібні файли проходять lifecycle detect → candidate → review → quarantine → delete. Система не повинна робити автоматичний hard-delete без review.
Навіщо пов’язувати вебакаунт із participant-профілем?
Це дозволяє показувати у власному кабінеті особисті бейджі та показники участі. Пов’язання виконує суперадміністратор.
