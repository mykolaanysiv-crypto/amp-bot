AMP XP / «АМПасадори» v1.10.3 — QA REPORT
================================================

RELEASE
-------
Version: 1.10.3
Name: Data Integrity & Data Quality Fix Pack

SCOPE
-----
P0 / Data Integrity:
- configurable event check-in window (default: 60 min before / 360 min after start);
- check-in blocked before opening and after closing of the window;
- attendance confirmation and XP award blocked outside the window unless staff uses an explicit manual override;
- manual attendance override requires a reason (minimum 5 characters) and is written to audit log;
- repeated check-in and repeated attendance confirmation remain idempotent;
- event time comparisons use the configured local timezone instead of Heroku/host UTC wall-clock;
- monthly/period reports separate completed, upcoming and in-progress events;
- future/in-progress events do not contribute attendance, average attendance or engaged-participant KPIs;
- legacy future-attendance rows are exposed as a data-integrity anomaly instead of being counted;
- “unique participants” now means actual engagement actions, not merely creation of a new profile;
- report KPIs are split into “for the period” and “snapshot as of report generation”.

Data Quality:
- new canonical settlement directory (`settlement_references`);
- aliases such as `Анисів`, `Анисiв`, `с.Анисів` are normalized to one canonical value;
- registration and web profile editing resolve settlement through the canonical directory;
- analytics, reports, broadcasts and Smart Opportunities compare normalized settlement values;
- Dashboard includes a Data Quality card with duplicate/noncanonical counters and an audited normalization action;
- fuzzy duplicate detection is conservative and report-only; it does not silently merge uncertain values.

SCHEMA
------
- SQLAlchemy tables: 48
- New table: settlement_references
- Migration style: additive/idempotent through existing Base.metadata.create_all()/bootstrap path.
