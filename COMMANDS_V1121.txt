АМПасадори v1.12.1 — Production Stability Gate
================================================

РЕКОМЕНДОВАНИЙ PRODUCTION FLOW: GitHub CI → Heroku deploy.
Не запускайте нову версію локально для production deploy.

1) Перед оновленням Heroku зробіть backup:

heroku pg:backups:capture -a amp-bot-ver-1-5-0
heroku pg:backups -a amp-bot-ver-1-5-0

2) Рекомендовані Config Vars для v1.12.1:

heroku config:set DB_POOL_SIZE=3 DB_MAX_OVERFLOW=2 DB_POOL_TIMEOUT=10 DB_POOL_RECYCLE=300 -a amp-bot-ver-1-5-0
heroku config:set WORKER_HEARTBEAT_SECONDS=30 WORKER_STALE_SECONDS=120 HEALTH_PROBE_TIMEOUT_SECONDS=3 HEALTH_STARTUP_GRACE_SECONDS=180 SCHEDULER_ALERT_REPEAT_SECONDS=3600 -a amp-bot-ver-1-5-0

MONOBANK_TOKEN, DATABASE_URL, WEB_SESSION_SECRET та інші існуючі секрети повторно вводити не потрібно.

3) Для обов'язкового CI deploy додайте GitHub repository secrets:

HEROKU_API_KEY
HEROKU_APP_NAME=amp-bot-ver-1-5-0

Після цього push/merge у main запускає PostgreSQL 16 CI. Deploy job виконається ТІЛЬКИ після PASS job `Production gate`.

4) Після deploy перевірте dynos:

heroku ps:scale web=1 worker=1 -a amp-bot-ver-1-5-0
heroku ps -a amp-bot-ver-1-5-0

Очікується:
web.1 up
worker.1 up

5) Health checks:

curl -i https://amp-bot-ver-1-5-0.herokuapp.com/health/live
curl -i https://amp-bot-ver-1-5-0.herokuapp.com/health/ready
curl -i https://amp-bot-ver-1-5-0.herokuapp.com/health/dependencies

/live → 200 якщо web process живий.
/ready → 200 лише якщо startup + DB + Alembic готові.
/dependencies → 200 лише якщо DB/Alembic/worker/schedulers healthy; інакше 503.

6) Логи:

heroku logs --tail -a amp-bot-ver-1-5-0

Успішний release містить повідомлення про lifecycle smoke PASS і production preflight PASS.

7) Emergency manual deploy (НЕ рекомендований як звичайний production flow):

Якщо GitHub недоступний і потрібен emergency hotfix, після ручної перевірки можна виконати git push heroku HEAD:main. Такий push обходить GitHub CI, тому використовуйте його лише аварійно.
