# Оновлення АМП XP до v1.7.0

## Що змінюється у БД

Оновлення additive та ідемпотентне:

- нова таблиця `participation_streaks`;
- нове поле `rewards.reward_type` (`item` / `streak_restore`).

Стандартний Heroku `release` / `db.init()` створить таблицю та додасть поле. Повторний запуск `migrate_sqlite_to_postgres.py` **не потрібен**.

## Безпечна послідовність

1. Зробити backup Heroku PostgreSQL.
2. Зберегти локальний `.env` поза Git-папкою.
3. Перенести файли v1.7.0 через `rsync` без `.git`, `.env`, `.venv`, `data`.
4. Оновити `requirements.txt` у локальному virtualenv.
5. Перевірити `VERSION.txt` та `app/version.py` → `1.7.0`.
6. Виконати `python -m compileall -q app scripts` та `git diff --check`.
7. Переглянути `git status`, закомітити тільки код v1.7.0.
8. `git push heroku main`.
9. Перевірити `/health` → `1.7.0`, `heroku ps`, `heroku logs --tail`.
10. Smoke-test: Telegram рейтинг, web `Рейтинг і серії`, призначення відповідального, спеціальна винагорода відновлення серії.

## Логіка ліг

- 🥉 Бронзова: 0–99 сезонного XP
- 🥈 Срібна: 100–249 XP
- 🥇 Золота: 250–499 XP
- 💠 Платинова: 500–999 XP
- 💎 Діамантова: 1000+ XP

## Серії

- Тижнева серія: щонайменше одна підтверджена позитивна XP-активність у календарному тижні. Поточний незавершений тиждень сам по собі серію не обриває.
- Суперсерія подій: можна пропустити одну подію поспіль і максимум дві події загалом у межах серії.
- Другий пропуск поспіль або третій пропуск загалом обриває суперсерію.
- 30+ днів чинної суперсерії → автоматичний бейдж.
- Після обриву остання серія може бути відновлена спеціальною винагородою за XP.
- Ручна корекція в web блокує автоматичне перезаписування цієї серії, доки адміністратор не натисне «Перерахувати з історії».
